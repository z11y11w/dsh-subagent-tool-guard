# 03 · 风险与边界

> 设计初稿 §3.9 列了 R1–R10。这里逐条**用源码重新判一次**，再补上实现过程中新发现的。

---

## 一、设计初稿 R1–R10 重评

### R1 · Team 队友被误伤 — **成立，已按"默认限制"处理**

- 证据：`dsh-agent-team/src/index.ts:65` 明说 teammates 是 subagent；`:80` 也用 `origin === 'subagent'` 排除队友。
- 结论：Team 队友会被同一判据命中。
- 处理：默认一起限制（与「子 agent 必须白名单」一致）；配置项 `restrictTeamMembers: false` 可放行。
  ⚠️ **这个开关是近似实现**：DSH 没有 `isTeamMember(agent)` 这种 API（`dsh-subagent` 的公开方法里没有），
  只能拿 `agentTeams.isEnabled(agent)`（`dsh-agent-team/src/index.ts:94`）判断"这棵树开没开 Team"。
  ⇒ Team 模式开着时，树里所有 subagent 都会被算作 Team 成员。
  ⇒ 这个近似只会让限制**更松**（多放行一批），不会把普通子代理误判成"该放行"的——Team 默认是关的。
- **误伤的实际后果没有想象中大**：只要队友用的 preset 自己装了工具（如 `my-preset`），它保留的就是那批工具；失去的只是"全局层白送的那些"——那正是要拿掉的东西。

### R2 · 插件加载晚于已有 agent — **成立，已实现补扫**

`agent/created` 只对将来生效。`installExisting()` 扫 `ctx.agents.list()`，`ctx.inject(['agents'])` 就绪后再扫一次，`guarded` 幂等。

### R3 · 紧急恢复通道缺失 — **成立，但严重性大幅下降**

- **这份方案不会让主 agent 失能**：判据是 `origin === 'subagent'`，主 agent 不命中，一条 restriction 都不会加到它身上。
- 设计初稿担心的是 `allow: []` 误判时把主 agent 关进笼子。那套方案已被否决（`docs/01` §2.3），这个风险随之消失。
- 仍然保留三道保险：
  1. 环境变量 `DSH_SUBAGENT_TOOL_GUARD_OFF=1` → 插件整体不生效
  2. `enabled: false` → 同样不生效
  3. 任何内部异常都 catch + 放行，不崩宿主

### R4 · 重入 / 事件循环 — **成立，已规避**

- 不监听 `tools/change`（restrict 会触发它，监听就可能闭环）
- `restrict` 调用在 try/catch 内
- 每个 agent 只处理一次（`guarded` 占位）

### R5 · 探针 / 内部会话可能被误伤 — **成立，且本方案确实没有解**

- `dsh-tool-manager` 会创建一个探针会话 `tool-manager-probe-internal-v1`，`origin: subagent`。
- 本插件按 `origin` 判据 ⇒ **那个探针也会被归零**，可能让 tool-manager 的某些能力失效。
- **当前不冲突**：`dsh-tool-manager` 是个可选插件，没装就没有这个问题。
- **若将来要装它**：需要先确认探针会话用哪个 preset，然后要么把那个 preset 加进 `skipPresets`，要么给本插件加一条按会话 id 的豁免。**这一项留待真机确认，不要凭猜写死。**

### R6 · `agent/created` 时 `agent.ctx` 可能没建好 — **成立，已防御**

`agent.ctx?.get?.('tools')` + `typeof restrict === 'function'` 双检，拿不到就 warn + 跳过。

### R7 · 多个插件同时 restrict 的叠加 — **成立，安全**

`dsh-tools/src/index.ts:214` 的 `layers.every(layer => layer.admits(name))` 就是"交集"语义：任何一层挡掉就挡掉。多个 restriction 只会更严，不会互相覆盖。
排查提示：本插件日志带 `[subagent-tool-guard]` 前缀，能和自己对上账。

### R8 · 孙代理（子代理再派子代理） — **成立，链式安全**

孙代理同样是 `origin: subagent`，同样被归零。**恰好证明"按身份判"优于"按 preset 判"**（设计初稿的判断是对的）。

### R9 · fork 出来的 agent 可能共享父的 ctx — **不成立（已证伪）**

`dsh-agent-loop/src/agent.ts:148`：`this.scope = createScope(loopCtx, this)` —— 每个 agent 一个独立 scope，key 就是 agent 对象本身。`restrict` 挂在 agent 自己的 ctx 上，不存在"父子共享"。隔离成立。

（附注：普通会话 fork **不带** `origin: 'subagent'`，所以根本不会命中本插件。）

### R10 · `restrict` 只挡工具，不挡"工具背后的能力" — **成立，写进使用说明**

子 agent 若仍保留 `web_fetch`，照样能抓网页；保留 `pwsh` 等于完全没限制。
**白名单的严格程度 = 那个 preset 装了什么**，插件只保证"没登记的不给"。

## 二、实现中新发现的风险

### N1 · `acquireScope` 租约泄漏

`agentPresets.acquireScope()` 会 `users++`，不 dispose 的话该 preset revision 永远不被 `collect()` 回收（内存 + 热重载行为都会异常）。
**处理**：`finally` 里 `await lease[Symbol.asyncDispose]?.()`，即使前面已经抛错也执行。

### N2 · shadow 工具被差集吞掉

preset 一层注册了与全局同名的工具时，两个视角都含这个名字 → 差集不含 → `allow` 里没有 → **被挡掉**（而不是"preset 版本生效"）。
这是"继承来的一个不留"的必然取舍。若确实需要，给该 preset 加进 `skipPresets`。

### N3 · `allow` 为空 = 哑巴子 agent

preset 没声明任何工具时 `allow = []`，子 agent 能推理不能干活，而且**不会报错，只会说"我做不到"**。
**处理**：
- 插件启动时对零工具 preset 打 `warn`
- 报告工具里 `empty: true`
- 文档和 DETAIL.md 里都写明"派活前先查报告"

### N4 · `agent/created` 里 await 可能拖慢派发

`acquireScope` 内部会 `await diagnostic()`，极端情况下会 `await loader.await()`（preset 有行在等 Host 服务时）。
**处理**：正常情况是微秒级（preset 树在 agent 创建前已挂载完成）；万一卡住，最坏结果是**这一次派发变慢**，不会死锁（不在 Host 行激活期间）。验证步骤 B 会实测这一点。

### N5 · 报告工具占全局层

`subagent_tool_report` 注册在插件 ctx（全局层），**所有主 agent 都能看到它**，多了一个工具定义（token 成本约几十）。不想要就 `registerReportTool: false`。

### N6 · 插件卸载后，已有子 agent 的限制何时解除

- 插件自己的 `ctx.effect` 清理函数会 `dispose()` 所有记录 ⇒ 立即解除
- 即使漏了，agent 销毁时 `agent.ctx` 的 effect 也会收回
- 但**已被限制的 agent 若在限制解除前已开始一个 step**，那个 step 仍用旧工具表（step 级快照）

## 三、能力边界（说清楚，别误解）

| 边界 | 说明 |
|---|---|
| agent 自己 scope 注册的工具 | **永远豁免**，插件改不了（`view()` 里 own 无条件可见） |
| 服务（不是工具） | `llm`、`session`、`sandbox`、`webServer`、`subagents` 等**完全不受影响**；被限制的子 agent 仍能推理、说话、存会话 |
| `run_code`（PTC 传输） | 源码明确拒绝出现在 allow/deny 里（`dsh-tools/src/index.ts:176-178`），也不受 restriction 影响 |
| working-directory | 挡掉 `tool-working-directory` 不代表子 agent 不知道自己在哪；cwd 是会话字段 |
| 未来的全局新工具 | 差集天然挡住（不在 allow 里） |
| 未来的 preset 新工具 | 若在 agent 创建**之后**才挂进同一个 preset revision，本 agent 的 `allow` 是快照，不会自动包含 → 需重启该子 agent |

## 四、和 `dsh-tool-manager` 的分工（避免两个插件互相打架）

本插件只管"安全"这一侧。如果还想省工具定义的 token，可以和按需分组的方案共存：

- 都调用 `agent.ctx.tools.restrict()`，restrictions **交集**生效（R7）
- tool-manager 的探针会话会被本插件归零（R5）→ 装之前先确认
- 本插件**不提供**"按需展开"能力（那需要 `tool_list`，等于给模型自己开锁的钥匙）——安全边界不能允许模型自己放开
