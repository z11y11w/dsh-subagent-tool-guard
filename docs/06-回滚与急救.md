# 06 · 回滚与急救

> 先说结论：**这个插件不会让主 agent 失能**。判据是 `origin === 'subagent'`，主会话不命中，一条 restriction 都不会加到主 agent 身上。最坏情况是「某个子代理工具少了」。

---

## 一、急救：立刻让插件失效（最快）

1. 设环境变量：

```powershell
[Environment]::SetEnvironmentVariable('DSH_SUBAGENT_TOOL_GUARD_OFF', '1', 'User')
```

或者在启动 DSH 的那个进程环境里设 `DSH_SUBAGENT_TOOL_GUARD_OFF=1`。

2. `continuum_restart`

3. 确认日志里有：

```
[subagent-tool-guard] 已通过环境变量 DSH_SUBAGENT_TOOL_GUARD_OFF=1 关闭，本次不施加任何限制
```

**注意**：环境变量在**进程启动时**读取。已经跑着的进程改了环境变量不会重新读。所以必须重启。

出问题解决后，把变量删掉：

```powershell
[Environment]::SetEnvironmentVariable('DSH_SUBAGENT_TOOL_GUARD_OFF', $null, 'User')
```

---

## 二、温和一点：只关掉功能，不卸载

改 profile 的插件行配置（插件详情页，或 `<DSH_HOME>/profiles/<profile>/cordis.patch.yml` 里 `subagent-tool-guard` 那一行）：

```yaml
- id: subagent-tool-guard
  config:
    enabled: false
```

重启。插件仍装载，但不施加任何限制、也不注册报告工具。

---

## 三、彻底卸载

1. 插件页面 → 卸载 `subagent-tool-guard`（会走 `plugin_manager` 的 `remove_bundle`）
2. `continuum_restart`

卸载时插件自己的 `ctx.effect` 清理函数会 `dispose()` 掉所有 agent 上的 restriction，**已有子代理立即恢复完整工具表**。

如果发现卸载后旧子代理仍然受限（理论上不该发生）：

- 那是残留的 scope registrations，重启 DSH 一定清干净（restriction 是进程内内存状态，不落盘）

---

## 四、只让某个 preset 不被限制

不改全局，只加白名单：

```yaml
- id: subagent-tool-guard
  config:
    skipPresets:
      - example-reader
      - my-preset
```

重启。这些 preset 派的子代理不受影响。

---

## 五、判断"是不是本插件干的"

| 症状 | 是不是本插件 | 怎么确认 |
|---|---|---|
| 子代理说"没有这个工具" | 可能是 | 日志搜 `[subagent-tool-guard] 限制子 agent` |
| 子代理干脆什么工具都调不了 | **可能是**（它的 preset 零工具） | 报告工具里看 `allowCount: 0`；日志搜 `⚠️ preset` |
| 主代理工具少了 | **不是** | 本插件只对 `origin=subagent` 的会话动手 |
| DSH 启动报某个 plugin 失败 | 可能是（但很轻） | 插件页面看该行状态；`noscreen` 里搜 `subagent-tool-guard` |
| Team 模式队友不能干活 | 可能是 | 设 `restrictTeamMembers: false` 试 |

---

## 六、本插件做过哪些**不会**做的事（降低你的排查面积）

- 不写任何会话事件（不改 session log）
- 不改 profile、不改 preset 定义
- 不碰文件系统（除了探针往 `~/.dsh/subagent-probe.jsonl` 追加）
- 不注册定时器、不发网络请求
- 不监听 `tools/change`（不会引起工具表回环）
- 不在主 agent 上添加任何 restriction
