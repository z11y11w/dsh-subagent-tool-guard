# 05 · 安装与验证步骤

> 前置：`docs/04` 的 A/B 两组你看过了、D 组做完了。
> 原则：**先装探针（只观测）→ 看数据 → 再装正式插件**。不要跳过探针。

---

## 步骤 1 · 装探针

1. 插件页面 → 添加插件 → 选本地目录 `tools/identity-probe/`
2. 确认 Plugins 里出现 `subagent-identity-probe`，状态是启用
3. `continuum_restart` 重启（不要手杀进程）

## 步骤 2 · 造四个样本

| 样本 | 操作 |
|---|---|
| 1 主 agent | 在当前会话说一句「你好」 |
| 2 普通子代理 | 让主代理调一次 `search_topic`（方向随便，例如「测试」） |
| 3 Team 队友 | 会话菜单 → `Select Agent Teams per Session` → 派一个队友做点小事 |
| 4 fork | 主代理调 `subagent_fork`，任务随便 |

## 步骤 3 · 读探针输出

```powershell
Get-Content '<DSH_HOME>\subagent-probe.jsonl' -Encoding utf8 |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Select-Object phase,
                agentId,
                @{n='origin';e={$_.header.origin}},
                @{n='depth';e={$_.header.delegationDepth}},
                presetId,
                toolsOnGlobal,
                toolsOnPresetScope,
                @{n='allowN';e={$_.wouldAllow.Count}},
                judgedAsSubagent |
  Format-Table -AutoSize
```

### 判定表

| 观察 | 结论 |
|---|---|
| 样本 1 `origin` 空、`judgedAsSubagent=false` | 判据不误伤主 agent ✅ |
| 样本 2 `origin=subagent`、`presetId=example-reader`、`wouldAllow` 非空 | 主路径可用 ✅ |
| 样本 4 `origin=subagent` | fork 子代理也会被限制（符合预期） |
| 样本 3 `origin=subagent` | Team 队友会被限制 → 按需设 `restrictTeamMembers: false` |
| 任何样本 `presetScopeError` 非空 | `acquireScope` 出问题，**停下来**，贴错误回来 |
| 样本 2 `wouldAllow` 是空的 | **硬失败**，先别装正式插件 |

顺便看一眼 `wouldAllow` 里到底有什么：

```powershell
Get-Content '<DSH_HOME>\subagent-probe.jsonl' -Encoding utf8 |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object { $_.presetId -eq 'example-reader' } |
  Select-Object -First 1 -ExpandProperty wouldAllow
```

期望：那个 preset 自己声明的工具都在（例如 `search_*` 系列）+ `web_search` / `web_fetch`。**不应该**出现 `dsh_browser_*`、`taskboard_*`、`read` / `write` / `pwsh`。

## 步骤 4 · 卸探针，装正式插件

1. 插件页面卸载 `subagent-identity-probe`
2. 添加插件 → 选本仓库根目录
3. 确认出现 `subagent-tool-guard`，**状态为启用**
4. `continuum_restart`

## 步骤 5 · 验收

按 `docs/04` 的 **E1–E7** 逐条跑。最快的三条：

**E1（子代理看不见浏览器）**
派一个 `example-reader` 子代理，让它「试着调用 dsh_browser_open 打开 example.com，把结果告诉我」。
期望：它报告工具不存在 / `UNKNOWN_TOOL`，并说明自己只能用 B 站工具。

**E2（子代理仍能干活）**
同一个子代理，让它 `search_queries` 一个关键词。
期望：正常返回结果。

**E3（主代理不受影响）**
在主会话直接调 `dsh_browser_open`。
期望：正常打开。

**E4（报告工具）**
主会话调 `subagent_tool_report`。
期望：看到刚才那个 `example-reader` 的 `allowCount` 与探针里的 `wouldAllow.Count` 一致。

## 步骤 6 · 若出问题

见 `docs/06-回滚与急救.md`。**最快的一招是设环境变量后重启**，不要先去卸载插件。

---

## 附：日志关键词

插件日志前缀固定为 `[subagent-tool-guard]`，搜这几个：

| 日志 | 含义 |
|---|---|
| `已启动（skipPresets=…` | 插件激活成功 |
| `限制子 agent <id>（preset=…` | 实际施加了限制（`verbose: true` 才有） |
| `⚠️ preset "x" 自己没有声明任何工具` | 零工具 preset，子代理会哑 |
| `施加工具限制失败，已放行` | 该子代理未被限制（安全方向） |
| `补扫：发现 N 个已存在的子 agent` | 晚加载补扫生效 |
| `已通过环境变量 … 关闭` | 急救开关生效 |
