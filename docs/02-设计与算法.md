# 02 · 设计与算法

## 1. 目标（按主代理/子代理分开）

| 对象 | 策略 | 依据 |
|---|---|---|
| 主 agent（主代理、lead、任何 `origin` 不是 `subagent` 的会话） | **完全不动** | 用户原则：「主 agent 只做礼貌的君子协议」 |
| 子 agent（`subagent` / `subagent_fork` / `search_topic` 派出的 / Team 队友） | **严格白名单**：只保留自己 preset 声明的工具 | 用户原则：「子 agent 必须严格白名单」 |
| 普通会话 fork | 不动（不是子 agent） | `header.origin` 为空（见 `docs/01` §2.4） |

---

## 2. 判据

```js
const isSubagent = (agent) => agent.session.header.origin === 'subagent'
```

- 写入点：`@deepseek-ai/dsh-subagent/src/child-agent.ts:150`（`childSessionMeta()`）
- 定义点：`@deepseek-ai/dsh-session/src/types.ts:122`
- 备用判据：`delegationDepthOf(agent) > 0`（`dsh-subagent/src/depth.ts:28`），指向同一批对象

**为什么不用别的判据**

| 候选 | 否决原因 |
|---|---|
| `agent.parentSession` 存在 | 会话注释明说 presence 不足以判定（普通 fork 历史上也可能带） |
| `agent.ctx` 是不是新对象 | `fork` 与 `spawn` 都新建 scope，主会话也新建，区分不出来 |
| `agent.options.subagentDepth` | 只在运行时传入，冷恢复的子 agent 可能没有；`header` 才是权威 |
| 按 preset 判断（设计初稿兜底方案） | 某个子代理没指定 preset 时会继承父的 preset，判据直接失效（设计初稿 R8） |

## 3. 核心算法：算 `allow` 而不是写死

### 3.1 为什么不能 `allow: []`

`restrict` 只过滤 **inherited**（全局层 + 祖先层），而 **preset 的行就挂在祖先 scope 上**。
`allow: []` ⇒ 连 preset 自己的工具一起消失 ⇒ 子 agent 变成"能说话没手"。详见 `docs/01` §2.2–2.3。

### 3.2 差集算法

```
globalNames = names( tools.definitions() )          // 全局层视角（不传 scope）
lease       = await agentPresets.acquireScope(presetId)
presetNames = names( tools.definitions(lease.key) ) // 全局层 + 该 preset 这一层
release(lease)
allow       = presetNames - globalNames             // ← preset 自己贡献的
tools.restrict({ allow })                           // 在这条 agent.ctx 上
```

- `tools.definitions(scope?)` 是 public API：`@deepseek-ai/dsh-tools/src/index.ts:305`
- `agentPresets.acquireScope(id)`：`dsh-agent-preset-registry/src/index.ts:389`，**必须** `[Symbol.asyncDispose]()`
- `restrict` 的 allow 名单必须是"全局或祖先"的已知名字，差集天然满足（preset 是祖先）—— `dsh-tools/src/index.ts:179-183`

### 3.3 为什么差集比 deny 清单好

| | `allow: 差集` | `deny: 全局工具清单` |
|---|---|---|
| 将来全局层新增工具 | **自动进不来**（不在 allow 里） | 漏（deny 是快照） |
| 维护成本 | 零 | 每次装新 bundle 都要补 |
| 语义 | 白名单（用户要求） | 黑名单（默认放行） |

### 3.4 已知取整（edge case，安全优先）

| 情况 | 结果 | 说明 |
|---|---|---|
| preset 一层注册了与全局**同名**的工具（shadow） | 该名字被两个视角都包含 → 被差集吞掉 → **整个工具消失** | 解释：这正是"继承来的一个不留"；若想保留要么改名、要么给该 preset 加进 `skipPresets` |
| preset 什么都没装 | `allow = []` → 子 agent 归零 | 会打 `warn`，`subagent_tool_report` 里 `empty: true` |
| preset 里的工具挂得更深（preset 内部又 createScope） | 差集按 preset 视角算，深层的名字不在 allow → 被挡 | 严格白名单的必然结果 |
| agent 自己 scope 注册的工具 | **豁免**（DSH 机制，`view()` 里 own 无条件可见） | 插件改不了，记在边界里 |

## 4. 时序

```
父 agent 调 subagent 工具
        │
        ▼
SubagentManager.startLocal()
        │  childSessionMeta()          → header.origin='subagent'
        │  applyChildComposition()     → await preset 挂载完成（工具已注册在 preset scope）
        ▼
ctx.agents.create() → AgentLoop 构造 → createScope(loopCtx, agent)
        │
        ▼
emit 'agent/created' { agent }        ← 我们的监听器在这里
        │  ★ DSH 会 await 监听器返回的 promise
        │
        ├─ isSubagent? 否 → return（主 agent 到此为止）
        ├─ presetId = composedPreset(agent.ctx) ?? header.agentPreset
        ├─ lease = acquireScope(presetId) → definitions(lease.key) → dispose lease
        ├─ allow  = presetNames - globalNames
        └─ agent.ctx.tools.restrict({ allow })   ← 限制已生效
        │
        ▼
ModelStep.prepare → tools.resolve(agent) → 只看到 allow 里的工具
        │
        ▼
agent/disposed → releaseAgent(agent) → disposer() + 清索引
```

**关键点**：因为 `agent/created` 的监听器会被 await（`dsh-agent/src/runtime-types.ts:279-291`），子 agent 的**第一个 step** 就已经是限制后的工具表，不存在"先跑一步再被收走"的窗口。

## 5. 失败模式与降级策略

原则：**宁可少限制一点，也不能把别人的子 agent 搞死。**

| 失败点 | 处理 |
|---|---|
| `agent.ctx.tools` 拿不到 | warn + 跳过该 agent（不限制，不崩） |
| 拿不到 preset id | warn + 跳过 |
| `acquireScope` 失败（preset 已不在注册表 / 内部错误） | 降级用 `definitions(agent)` 视角算差集；**若降级后 restrict 因 unknown 名字抛错 → catch 住并放行**，warn 说明 |
| `restrict` 抛错（名字未知、ctx 过期） | catch，删掉占位记录，warn；**该子 agent 不限** |
| 报告工具注册失败（重名 / schema 被拒） | warn，不影响限制功能 |
| 同 agent 重复进入（created 与补扫撞车） | 占位 `Map` + 单个 `guarded.has()` 判断，天然幂等 |

**插件自己永远不因为异常而让宿主崩**：所有回调体内的异常都就地吞掉并记 `warn`。

## 6. 生命周期与卸载

- `restrict()` 的 disposer 用 `agent.ctx` 作为 effect 的 owner ⇒ agent 销毁时 DSH 会自动收回。
- 但 **practices 明确说过**：卸载插件**不会**自动清 agent.ctx 上的注册（`references/practices.md:19`）。所以：
  - 每个 agent 的 disposer 都存进插件自己的 `Map`
  - `agent/disposed` → 立刻 `dispose()`
  - 插件 `ctx.effect` 的清理函数 → 遍历 `Map` 全部 `dispose()`
- 索引（`presetIndex`）只存 `{preset → {allow, agents}}`，**不持有 agent 引用**，不会阻止 GC。

## 7. 配置项

| 键 | 类型 | 默认 | 作用 |
|---|---|---|---|
| `enabled` | bool | `true` | 总开关（false = 完全不进入逻辑） |
| `skipPresets` | string[] | `[]` | 这些 preset 的子 agent 不限制 |
| `restrictTeamMembers` | bool | `true` | Team 队友（同为 subagent）是否一起限制。**近似判断**：用 `agentTeams.isEnabled(agent)`，不是精确的"是不是队友"（DSH 无此 API） |
| `registerReportTool` | bool | `true` | 是否注册只读工具 `subagent_tool_report` |
| `warnOnEmptyPreset` | bool | `true` | preset 零工具时告警 |
| `verbose` | bool | `false` | 每个 agent 一行日志 |

配置值全部经过**类型收敛**（`pickBool` / `pickStringArray`），非标量一律回落默认值 —— 这是被 2026-10-14 那次「config 字段不是标量 ⇒ 定时器里抛错 ⇒ 整个宿主进程被带走」的事故教出来的规矩。

## 8. 只读报告工具 `subagent_tool_report`

- 注册在**插件自己的 ctx**（= 全局层）⇒ 主 agent 天生可见
- 子 agent 被 `allow` 挡掉 ⇒ 子 agent **看不到**它（正合需要）
- 输出结构固定，`additionalProperties: false`（DSH 的 JSON Schema 校验要求）

返回样例：

```
子 agent 工具白名单：当前生效 2 个子 agent。

· preset example-reader（1 个 agent）：保留 15 个工具
  search_topic, search_queries, read_transcript, …, web_search, web_fetch
· preset empty-preset（1 个 agent）：保留 0 个工具 —— ⚠️ 一个都没有！
```

**用途（对应设计初稿 §3.5 的防呆要求）**：主 agent 派活之前先看一眼，就知道「这个 preset 到底还能干什么」。`allowCount === 0` 的 preset 不要用来派活。

---

## 9. 补扫与热加载

- `apply()` 末尾立刻 `installExisting()`：扫 `ctx.agents.list()`，对已是 subagent 的补加限制。
- 再用 `ctx.inject(['agents'], …)` 在 agents 服务就绪后**再扫一次**（`guarded.has()` 保证幂等）。
- 这样「插件晚于会话加载 / HMR / 重启恢复」都不会出现"老会话还能用浏览器"的假阴性（设计初稿 R2）。
- 不监听 `tools/change`：避免 restrict → tools/change → 重入的回环（设计初稿 R4）。
